# گزارش بررسی 2.0.167-subscription-plus

تاریخ: ۲۰۲۶/۱۰/۲۶. مبنا: بسته 2.0.166 شامل قابلیت چند واریزی/چندفیش. هیچ اتصال به دیتابیس سایت مشتری، ارسال پیامک واقعی یا انتقال اعتبار به مقصد در این بررسی انجام نشده است.

## نتیجه اجرا

| بررسی | نتیجه |
| --- | --- |
| نحو ۴۵ فایل PHP، شامل کد و تست‌ها، با PHP CLI 8.3.6 | موفق |
| نحو ۴۱ فایل JavaScript، شامل کد و تست‌ها، با node --check | موفق |
| ۳۰ فایل تست اجرایی PHP/JS/Python | همه موفق |
| تست اختصاصی اشتراک+ با PHP | ۵۳ بررسی موفق |
| فرم فروش اشتراک+ با jsdom و jQuery 3.7.1 | ۱۶ بررسی موفق |
| اجرای دستور ساخت جدول جدید در MariaDB 10.11 به روش bootstrap | موفق؛ فقط صحت DDL |
| مقایسه static-audit با بسته مبنا | همان شش گزارش قبلی؛ بدون گزارش تازه |
| آزمون کامل روی وردپرس، ووکامرس و درگاه واقعی | انجام نشده |

تست‌های اختصاصی از کلاس واقعی اشتراک+ و بدنه متدهای واقعی صدور فاکتور، ساخت پرونده دات، ساخت فاکتور تبدیل و ثبت پورسانت استفاده می‌کنند. وردپرس، ووکامرس، HR، پیامک، مرز کیف پول و wpdb با نمونه‌های آزمایشی جایگزین شده‌اند. رفتار تراکنش و rollback در این تست‌ها شبیه‌سازی شده است؛ این نتیجه جای آزمون هم‌زمانی و تراکنش واقعی MySQL روی نصب سایت را نمی‌گیرد.

## پوشش اشتراک+

- تفکیک اعتبار اسمی از قیمت فروش و محاسبه ۱۰+۵=۱۵ میلیون؛ عدم اعتماد به قیمت نقدی ارسالی از مرورگر.
- انتخاب صریح بدون نقدی، گزینه نامعتبر، محصول مخلوط، مبلغ منفی، ارقام فارسی، تعداد یک و محدودیت پرداخت اولیه کامل.
- ثبت فاکتور و اسنپ‌شات در یک مرز تراکنش؛ rollback درج ناموفق، BEGIN/COMMIT ناموفق و توقف روی موتور غیرتراکنشی.
- ورود مستقیم همراه نقدی؛ صف تبدیل بدون نقدی؛ مالک تبدیل توسط خود فروشنده؛ حذف تصمیم پیامک اعتبارسنجی.
- تکمیل بدون نقدی بدون فاکتور اضافه؛ فاکتور تبدیل فقط به مبلغ ۵ میلیون، با نوع مستقل نقدی.
- جلوگیری از اعطای اعتبار پیش از پرداخت، پرونده ظاهراً تکمیل‌شده با فاکتور پرداخت‌نشده و مبلغ تبدیل ناسازگار.
- دو اعتبار جدا، یک کارت و یک عضویت در تکرار callback؛ ثبات payload فعال در callback تکراری.
- پورسانت مستقل از قیمت پایه و قیمت نقدی؛ نمونه نرخ ۱۰٪ و ۵٪، جلوگیری از ثبت دوباره هر مؤلفه.
- تعلیق روی برگشت مالی و استفاده مجدد از همان عضویت پس از تأیید مجدد.
- حفظ اعتبار و قیمت خرید قبلی با تغییر محصول؛ تصویر/توضیح/مقصد کارت خودش و حذف مسیر فعال‌سازی.
- جلوگیری از تبدیل فاکتور معمولی به اشتراک+ از ویرایشگر عمومی و دورزدن اعتبارسنجی گزینه نقدی.
- مبلغ نمایشی ۱۵ میلیون، انتقال شناسه گزینه به درخواست، متن امن عنوان و برگشت صحیح فرم به رفتار اعتبارسنجی/محصول معمولی پس از تغییر انتخاب.

## رگرسیون‌های اجراشده

تست‌های قبلی مربوط به پرداخت چندفیش، واریزی مستقل و batch، بررسی مالی، رد مالی، فاکتور مرحله بعد، دسترسی عملیات، SMS و تعویض سرویس، کاتالوگ فروش، HR، همگام‌سازی کارت، دعوت/فرم بیاوین و فیلترهای فاکتور همگی موفق بودند. قابلیت batch نسخه 2.0.166 در این محیط برای اولین بار با PHP CLI نیز اجرا شد.

دو اصلاح صرفاً در fixture تست قدیمی انجام شد: تکمیل فیلدهای اختیاری ردیف بانکی در تست batch و هماهنگی نسخه cache آزمایشی HR با نسخه موجود کد. منطق عملیاتی این دو بخش تغییر نکرد.

## شش گزارش پیشین ابزار ایستا

این موارد در اجرای یکسان ابزار روی بسته مبنا و بسته جدید دقیقاً یکسان بودند و در محدوده این تغییر اصلاح نشده‌اند. بنابراین static-audit به‌طور کامل سبز نیست:

۱. نبود رشته تشخیصی `sn_zibal_export_log($request_id, 'merge'` در خروجی زیبال.

۲. عدم تطبیق کنترل رشته‌ای ابزار برای تازه‌سازی صف تبدیل هنگام بازشدن تب.

۳. گزارش تابع تاریخ در `class-sn-bulk-order-export.php`.

۴. گزارش تابع تاریخ در `class-sn-invoice-review.php`.

۵. نبود رشته `remote_report_fallback` مورد انتظار ابزار.

۶. نبود رشته `fflush($out)` مورد انتظار ابزار.

این گزارش اثبات بی‌اشکال‌بودن کل افزونه نیست. اجرای سناریوهای راهنمای `SUBSCRIPTION_PLUS_2.0.167.md` روی نسخه آزمایشی همسان سایت، پیش از جایگزینی در سایت اصلی، هنوز لازم است.

## اجرای دوباره تست اختصاصی

```sh
php -l includes/class-sn-subscription-plus.php
php tools/test-subscription-plus.php
NODE_PATH=/path/to/node_modules node tools/test-subscription-plus-ui.js
```

برای تست DOM، بسته‌های `jsdom` و `jquery@3.7.1` لازم‌اند. تعدادی از تست‌های قدیمی UI به fixture تولیدشده توسط تست PHP هم‌نام نیاز دارند؛ ترتیب تولید در ابتدای همان فایل تست توضیح داده شده است. فایل‌های runtime، وابستگی‌های آزمون و دیتابیس آزمایشی در بسته نصب قرار نگرفته‌اند.
